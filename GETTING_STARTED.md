# Getting Started — haven

How this repository is organised, how to set up a workstation, and how a change
goes from `config/` to production with strata v2.

---

## Repository layout

```
strata.yaml        Solution manifest — names the solution, excludes .archive/ and Helm templates
config/            Every strata document (found by walking the tree, referenced by name):
  configuration.yaml     provider/topology registry, allowed secret stores
  registry/              providerconfig (hetzner), topologyconfig (compose, k3s)
  integrations/          terraform, infisical
  attributes/            schema checks (VM settings, deployment properties)
  providers/             the Hetzner project
  hearth/  forge/        each VM: resource (vm.yaml), firewall, namespace(s), modules
  environments/prd.yaml  all secrets (Infisical) — the 55 keys
  workspace.yaml         what gets deployed: provisioners, execution steps, topologies
  deployment.yaml        haven_deploy_prd = workspace + environment
services/          Hearth's Caddyfile and Forge's local Helm charts
deploy/            terraform/ (Hetzner) and ansible-hearth/, ansible-forge/ (VM setup)
.github/           workflows and the setup-tools action
scripts/           check-helm-braces.ps1, hash_argon2.py
docs/              Sphinx documentation
VERSIONS.env       Tool versions — the single place to change them
.strata/           Generated by strata (schemas, README) — never edit by hand
build/             Output of `strata build run` (gitignored)
```

## Workstation setup

1. Install Python and the tools at the versions in [`VERSIONS.env`](VERSIONS.env)
   (see [docs/guides/prerequisites.md](docs/guides/prerequisites.md)), or open the
   repo in the devcontainer, which installs them all.
2. Create a virtual environment with strata:

   ```bash
   uv venv .venv
   uv pip install --python .venv "xyz-strata @ git+https://github.com/huybrechtsxyz/strata.git@v2.7.0"
   .venv/Scripts/activate        # Windows; `source .venv/bin/activate` elsewhere
   strata --version              # strata, version 2.7.0
   ```

3. To resolve secrets locally, set the Infisical machine identity in your shell
   (never in a file in the repo): `INFISICAL_CLIENT_ID`, `INFISICAL_CLIENT_SECRET`,
   `INFISICAL_PROJECT_ID`. Validating and building need none of them.

## Everyday commands

strata always names the deployment as an argument — there is no `-f`/`--file`.

| Task | Command |
| --- | --- |
| Validate every document | `strata validate --strict` |
| Show cross-references / unused documents | `strata graph --unreferenced` |
| Show a resolved document and where each field comes from | `strata render deployment haven_deploy_prd` |
| List the steps a deploy runs, in order | `strata deploy steps haven_deploy_prd` |
| Check that the tools are installed | `strata integration list` |
| Render everything into `build/haven_deploy_prd/` | `strata build run haven_deploy_prd` |
| List secrets without revealing them | `strata values list haven_deploy_prd` |
| Check every secret resolves (needs Infisical) | `strata values resolve haven_deploy_prd` |
| Write or generate a secret | `strata values set haven_deploy_prd --key KEY --generate` (or `--value`, `--stdin`) |
| Help for any command | `strata <command> --help` |

Never use `strata values get` to *look at* configuration: it prints secrets in clear
text. It exists for the workflows and for piping (see
[the hashed-secret cookbook](docs/cookbooks/hash-secret-before-storage.md)).

## How a change reaches production

The deployment `haven_deploy_prd` runs three steps (`strata deploy steps haven_deploy_prd`):

| Step | Tool | What | Run by |
| --- | --- | --- | --- |
| `infrastructure` | Terraform | both VMs, firewalls, network, SSH key | `10 - Infra - haven` (`deploy run --scope infra`) |
| `applications_hearth` | Compose | renders Hearth's `docker-compose.yml` — **build only** | `23 - Hearth - Deploy` copies it via Ansible |
| `applications_forge` | Helm | Forge's namespaces, in the listed order | `33 - Forge - Deploy` (`deploy run --stage applications_forge`) |

1. Edit `config/` (or a chart under `services/`), then run `strata validate --strict`
   and `strata build run haven_deploy_prd` locally.
2. Open a PR — `CI - Build` repeats validate + build, lints every chart and runs
   `terraform fmt`/`validate`.
3. Run the workflow for what changed (Infra, Hearth or Forge) from a feature branch.

**Hearth is never deployed by strata.** strata's Compose deployer targets Docker
Swarm; Hearth runs plain `docker compose`, driven over SSH by Ansible. The
deployment's `docker_context` deliberately names a context that does not exist, so a
`strata deploy run` that selects `applications_hearth` stops before changing
anything.

## Adding things

- **A secret** — add a `key`/`store: infisical`/`value` entry (with `generate:` for
  random values) to `config/environments/prd.yaml`, then use it as
  `${secret:KEY}` in a module. For an app's own `${...}` syntax inside a module,
  write `$${...}`.
- **A Forge app** — add a module under `config/forge/modules/` (a local chart under
  `services/forge/<name>/` or a registry chart via `chart_repository`), list it in a
  namespace under `config/forge/namespaces/`, and make sure the namespace is in
  `config/workspace.yaml`.
- **A Hearth service** — add a Compose module under `config/hearth/modules/` and
  list it in `config/hearth/namespaces/hearth.yaml`.

Lessons learned along the way are in the `project-gotchas` skill
(`.claude/skills/project-gotchas/SKILL.md`); strata's own reference is
`.claude/skills/strata/SKILL.md` and `.strata/README.md`.
